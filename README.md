# Домашняя работа №1: От Core к Web.

**любой сервер в конечном итоге просто отдает клиенту (браузеру) текст в определенном формате.**

Эта работа состоит из двух уровней сложности. Вы сами выбираете, на какой балл претендуете.

---

## Уровень 1: Base Web (Оценка: 60%)

**Ваша задача:** Найти референс сайта (или продумать дизайн для вашей будущей семестровой работы) и сверстать главную страницу на чистом HTML (CSS приветствуется, но не оценивается строго).

### Что нужно изучить для выполнения:
Для успешной сдачи этого блока вам необходимо самостоятельно разобраться со следующими темами:
1. **Базовая структура документа:** `<!DOCTYPE html>`, `<html>`, `<head>`, `<body>`, `<meta>`, `<title>`.
2. **Семантические теги (HTML5):** Почему нужно использовать `<header>`, `<main>`, `<footer>`, `<nav>`, `<section>`, `<article>`, вместо того чтобы всё делать через `<div>`.
3. **Текстовые элементы:** Заголовки (`<h1>` - `<h6>`), абзацы (`<p>`), списки (`<ul>`, `<ol>`, `<li>`), ссылки (`<a>`).
4. **Медиа-контент:** Изображения (`<img>` и атрибут `alt`).
5. **Таблицы:** `<table>`, `<tr>`, `<td>`, `<th>`, `<thead>`, `<tbody>`.
6. **Формы ввода (база для будущего):** `<form>`, `<input>` (разные типы: text, password, submit), `<button>`.

**Результат:** Файл `index.html`, который корректно открывается в браузере и визуально передает структуру задуманного вами сайта.

## Уровень 2: Java HTML Generator (Оценка: 100%)

**Ваша задача:** Написать на чистой Java (используя только Core) ООП-движок для генерации вашего `index.html` из Уровня 1.

### Техническое задание (ТЗ) на архитектуру движка:

1. **ООП и SOLID:**
    * HTML-элементы должны быть представлены в виде объектов. Создайте базовый интерфейс `HtmlNode` с методом `String render()`.
    * Реализуйте классы для разных тегов (например, `DivElement`, `TextElement`, `ImgElement` и т.д.). Используйте паттерн *Composite (Компоновщик)* для вложенных элементов.

2. **Рефлексия и Аннотации:**
    * Создайте свою аннотацию `@WebComponent(tag = "...", cssClass = "...")`.
    * Напишите класс, например, `PageData`, поля которого размечены этой аннотацией.
    * Ваш генератор должен через **Reflection API** пройтись по объекту `PageData`, прочитать аннотации и автоматически собрать из них DOM-дерево (дерево HTML-узлов).

3. **Stream API и Многопоточность (Важное требование оптимизации!):**
    * Представьте, что ваша страница генерирует таблицу или галерею из 100 000 элементов.
    * **Обязательное условие:** Рендеринг вложенных коллекций (например, списка `<li>` внутри `<ul>` или строк `<tr>` внутри таблицы) должен происходить **параллельно** с использованием `parallelStream()` или пула потоков.
    * *Примечание:* Убедитесь, что после параллельного рендеринга структура вашей страницы не разрушается, а потоки не блокируют друг друга.

4. **I/O Потоки:**
    * Сгенерированная строка или поток байтов должны записываться в файл `output.html` на диске.
    * Использовать классы из пакетов `java.io`. Обязательно обеспечьте корректное закрытие ресурсов (try-with-resources) и правильную кодировку (UTF-8).

5. **Тестирование:**
    * Напишите минимум 3 Unit-теста (JUnit), которые проверяют:
        - Корректность рендеринга отдельного тега.
        - Работу рефлексии (правильно ли парсятся аннотации).
        - Работу генератора с пустой коллекцией дочерних элементов.

### Как сдавать работу:
1. Показать исходный `index.html` (или референс).
2. Запустить Java-приложение.
3. Продемонстрировать, что сгенерированный `output.html` идентичен эталонному.
4. Ответить на вопросы по коду (почему выбраны такие коллекции, как работает рефлексия, как управляются потоки).
5. Cоздать репозиторий и запушить решение в master/main.
