# Домашняя работа №2: API для Маркетплейса

Ваша задача — реализовать фундамент нашего веб-приложения, используя исключительно Java Servlets (Jakarta EE). Мы должны спроектировать HTTP API, которое будет принимать запросы от клиентов и возвращать текстовые ответы, эмулируя полноценную работу магазина.

## Архитектура и хранение данных (Моки)
Поскольку мы пока не работаем с базой данных, все данные должны храниться в оперативной памяти сервера во время его работы. Не пишите бизнес-логику прямо в сервлетах! Создайте отдельные классы-сервисы (например, ``` ProductService ```, ``` UserService ```) и храните данные внутри них, используя статические коллекции (например, ``` List<String> ``` или ``` Map<Integer, String> ```). Сервлеты должны заниматься только своей прямой обязанностью: принять HTTP-запрос, вытащить из него параметры, передать их в слой сервисов, получить результат и сформировать HTTP-ответ с правильным статус-кодом.

### Требования к логированию

В разработке категорически не рекомендуется использовать ``` System.out.println ```для вывода информации о работе приложения. Во всем проекте вы должны использовать библиотеку SLF4J. Добавьте необходимые зависимости в ``` pom.xml ```(API slf4j и реализацию logback-classic). В ресурсах проекта (``` src/main/resources ```) создайте файл ``` logback.xml ``` со следующей конфигурацией, чтобы логи красиво выводились в консоль:

```xml
<configuration>
    <appender name="STDOUT" class="ch.qos.logback.core.ConsoleAppender">
        <encoder>
            <pattern>%d{HH:mm:ss.SSS} [%thread] %-5level %logger{36} - %msg%n</pattern>
        </encoder>
    </appender>

    <root level="info">
        <appender-ref ref="STDOUT" />
    </root>
</configuration>
```

В каждом сервлете (или сервисе) добавьте логгер (через аннотацию ```@Slf4j ``` из Lombok или вручную:
```Java 
private static final Logger log = LoggerFactory.getLogger(<CLASS_NAME>.class)); 
```
Логируйте каждый входящий запрос: какой метод вызван, какие параметры переданы.

### Описание API

Для обеспечения работы маркетплейса вам необходимо создать независимые сервлеты, которые покроют основные потребности пользователей и администраторов.

Первым делом нам понадобится управлять товарами. Создайте ``` ProductServlet ``` (путь ``` /api/products ```), который будет обрабатывать два типа запросов. При получении GET-запроса сервлет должен возвращать текстовый список всех доступных товаров из вашего мок-хранилища. Если же приходит POST-запрос с параметром названия товара в теле запроса, сервлет должен добавить этот товар в коллекцию и вернуть статус ``` 201 Created ``` с сообщением об успешном добавлении.

Далее необходимо реализовать управление профилем покупателя через ``` UserServlet ```(путь ``` /api/users ```). При GET-запросе с параметром id в URL возвращайте информацию о пользователе. Для полного обновления профиля (например, имени и email) обработайте PUT-запрос, заменяя старые данные пользователя на новые. Также мы хотим позволить пользователям менять только статус аккаунта (например, с "active" на "blocked") без передачи остальных данных — для этого реализуйте обработку PATCH-запроса. Обратите внимание: стандартный класс ``` HttpServlet ``` зависимо от версии не содержит или содержит метод ``` doPatch```, но реализация контейнером сервлетов может быть проигнорирована. Вам придется переопределить метод ``` service```, проверить, равен ли ``` req.getMethod()``` строке "PATCH", и если да — выполнить нужную логику, а иначе вызвать ``` super.service(req, resp)```.

Пользователь должен иметь возможность собирать товары для покупки. За это будет отвечать ``` CartServlet ``` (путь ``` /api/cart ```). POST-запрос с идентификатором товара должен добавлять его в корзину пользователя. Для просмотра содержимого корзины используйте GET-запрос, а если пользователь передумал и хочет убрать товар из корзины — обработайте DELETE-запрос, удаляя соответствующий элемент из коллекции.

Оформление покупок вынесите в ``` OrderServlet ``` (путь ``` /api/orders```). Когда корзина собрана, POST-запрос на этот эндпоинт должен эмулировать создание заказа (можно просто очищать корзину и добавлять запись в коллекцию заказов). GET-запрос должен позволять просмотреть историю уже оформленных заказов.

Чтобы магазин развивался, клиенты должны оставлять отзывы. Реализуйте ``` ReviewServlet ``` (путь ``` /api/reviews```). POST-запрос с текстом отзыва и ID товара сохраняет мнение клиента. Если отзыв нарушает правила, модератор должен иметь возможность удалить его с помощью DELETE-запроса.

Наконец, нам нужна статистика для руководства магазина. Создайте ``` AdminStatServlet ```(путь ``` /api/admin/stats```). Этот сервлет должен реагировать только на GET-запросы и возвращать общую информацию (количество зарегистрированных пользователей, общее число добавленных товаров). Однако, это закрытый эндпоинт. В сервлете необходимо проверять наличие HTTP-заголовка Admin-Token. Если заголовок отсутствует или содержит неверное значение, возвращайте статус ``` 401 Unauthorized``` или ```403 Forbidden```. Если токен верен — отдавайте статистику.

### Как тестировать API без браузера (Инструкция по cURL)

Браузерная строка умеет отправлять только GET-запросы, а HTML-формы ограничены GET и POST. Поскольку мы пишем полноценное API и используем методы PUT, PATCH и DELETE, для тестирования вам понадобится терминал (командная строка) и утилита curl, которая встроена в современные версии Windows, macOS и Linux.

Откройте терминал и используйте следующие команды для проверки ваших сервлетов. **Подготовьте файл со всеми запросы к API!!!**

#### Тестирование GET (Просмотр товаров и логов):

```bash
  curl -X GET http://localhost:8080/api/products
```

#### Тестирование POST (Добавление товара, данные передаются как форма):
```bash
  curl -X POST -d "name=MacBook Pro" http://localhost:8080/api/products
```

#### Тестирование PUT (Полное обновление пользователя):
```bash
  curl -X PUT -d "name=Ivan" -d "email=ivan@test.com" http://localhost:8080/api/users?id=1
```

#### Тестирование PATCH (Частичное обновление профиля):
```bash
  curl -X PATCH -d "status=blocked" http://localhost:8080/api/users?id=1
```

#### Тестирование DELETE (Удаление товара из корзины):
```bash
  curl -X DELETE http://localhost:8080/api/cart?productId=5
```

#### Тестирование заголовков (Проверка админ-панели):
```bash
  # Должен выдать ошибку 401/403
  curl -X GET http://localhost:8080/api/admin/stats

  # Должен выдать статистику (200 OK)
  curl -X GET -H "Admin-Token: super-secret-key" http://localhost:8080/api/admin/stats
```

Примечание для пользователей Windows (cmd/PowerShell): Если возникают проблемы с двойными кавычками, убедитесь, что вы используете стандартную командную строку (cmd) или экранируете параметры должным образом.

**Не забывайте следить за логами сервера в вашей IDE!**
